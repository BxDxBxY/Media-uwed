## 4. 🔴 Critical

### C1 — Content CRUD is fully unauthenticated (anyone on the internet can create/edit/delete)

The admin UI performs all content mutations through the **public** `/api/frontend/*` routes ([lib/context.tsx:256-381](../lib/context.tsx)), and those handlers contain **no session check at all**:

- [app/api/frontend/articles/route.ts:164](../app/api/frontend/articles/route.ts) — `POST` create
- [app/api/frontend/articles/[id]/route.ts:29](../app/api/frontend/articles/[id]/route.ts) — `PUT`, `:81` `DELETE`
- [app/api/frontend/events/route.ts:28](../app/api/frontend/events/route.ts) — `POST`; [events/[id]:5,65](../app/api/frontend/events/[id]/route.ts) — `PUT`/`DELETE`
- [app/api/frontend/media/route.ts:35](../app/api/frontend/media/route.ts) — `POST`; [media/[id]:24,46](../app/api/frontend/media/[id]/route.ts) — `PUT`/`DELETE`
- [app/api/frontend/seed/route.ts:6](../app/api/frontend/seed/route.ts) — `POST` seeds content **and creates an admin user with password `Admin123!`** if `DEMO_ADMIN_PASSWORD` is unset (guarded only by "DB has no articles/events")

**Verified empirically** (no cookies sent):

```
POST   /api/frontend/articles                        → 400  (validation, not 401)
DELETE /api/frontend/articles/00000000-...-000000000000 → 404 {"error":"Article not found"}
PUT    /api/frontend/events/00000000-...-000000000000   → 404 {"error":"Event not found"}
GET    /api/admin/dashboard                          → 401  (admin routes ARE protected)
```

Reaching validation/404 instead of 401 proves the handlers execute for anonymous callers.

**Fix:** add `requireAdmin(request)` to every non-GET handler under `app/api/frontend/**` (or move admin CRUD to `/api/admin/*` and keep `frontend` read-only). Delete or gate `frontend/seed`.

### C2 — Self-service privilege escalation to full admin

Public signup exists ([app/api/admin/auth/signup/route.ts](../app/api/admin/auth/signup/route.ts), page `/admin/signup` → HTTP 200, linked from [app/admin/login/page.tsx:103](../app/admin/login/page.tsx)) and correctly creates users with `approved=false`, `role="admin"`.

But the password-reset handler flips the approval flag:

```ts
// app/api/admin/auth/reset-password/route.ts:38
approved: true, // Automatically approve them if they resets password? Wait, no, ...
```

**Attack chain:** register with own email → `POST /api/admin/auth/forgot-password` (unauthenticated, emails/prints the reset link) → reset password → `approved=true`, `role="admin"` → login succeeds and `(protected)` layout admits the user. The super-admin approval queue in [approvals/page.tsx](<../app/admin/(protected)/approvals/page.tsx>) is bypassed entirely.

Additional aggravating factors: **no rate limiting anywhere** (grep for `rateLimit` → nothing), and `forgot-password` returns the reset link in the JSON body whenever the request `Host` contains `localhost`/`127.0.0.1` — a header the client controls.

**Fix:** remove `approved: true` from reset-password; require an existing approved account for reset; close/rate-limit signup; do not key "dev mode" off the `Host` header.

### C3 — Schema/migration drift: a clean deploy will crash

`prisma/schema.prisma` (uncommitted changes) adds to `AdminUser`: `approved`, `resetToken`, `resetTokenExpires`, `isSuperAdmin` — and adds `IntegrationConfig.providerBaseUrl`.

`providerBaseUrl` has a migration. **The four `AdminUser` columns do not** (`grep -rl "approved\|isSuperAdmin\|resetToken" prisma/migrations/` → empty). They exist in the local DB only because they were pushed directly (`prisma db push`).

Consequence: on a fresh environment `prisma migrate deploy` creates `admin_users` **without** those columns, and then login, `(protected)/layout.tsx`, signup, approvals and reset all fail with Prisma "column does not exist".

Also review **migration `20260718222543_add_provider_base_url`** — it is destructive beyond its name:

```sql
DROP TABLE "admin_broadcast_logs";
ALTER TABLE "contact_messages" DROP COLUMN "lastReplySubject", DROP COLUMN "repliedAt";
```

(No code references those objects any more, so the drop is consistent with the schema — but it will destroy data on any environment that has it.)

**Fix:** `npx prisma migrate dev --create-only -n add_admin_approval_and_reset`, review the SQL, commit it, and verify against a scratch database before deploying.

### C4 — Automation endpoints are open

[cron/pull](../app/api/cron/pull/route.ts), [cron/process](../app/api/cron/process/route.ts) (`maxDuration = 300`) and [cron/publish](../app/api/cron/publish/route.ts) have **no auth**. Anyone can burn AI credits, hammer sources, **publish articles, and trigger Telegram broadcasts**.

[cron/automation/route.ts:8](../app/api/cron/automation/route.ts) does check a secret — but **fails open**: if `AUTOMATION_CRON_SECRET` is unset it returns `true`.

**Fix:** one shared mechanism for all four (`AUTOMATION_CRON_SECRET` header or `requireAdmin`), and make it **fail closed** when the secret is missing.

### C5 — Production build does not build

Both bundlers fail on this machine:

- `next build --webpack` → `Error: EISDIR: illegal operation on a directory, readlink 'D:\...\app\api\admin\<varies>\route.ts'`. The file named in the error **changes between runs** (`admin/about`, `admin/auth/reset-password`), which points at a filesystem/worker race rather than a real source problem. Reproduced on a clean `.next`.
- `next build` (Turbopack) → `failed to write .next/server/chunks/[externals]_node:buffer_*.js.map` / `os error 123` — the `:` in `node:buffer` is an illegal Windows filename character.
- `npm run build` never even reaches the bundler: the script starts with `DATABASE_URL=${DATABASE_URL:-...} prisma generate`, which is POSIX-only syntax.

**Impact:** no release artifact can be produced locally; `npm start` is unusable. The Turbopack failure is Windows-specific and would likely not reproduce on Linux/Vercel — **that must be confirmed on a Linux runner before treating this as Windows-only.**

**Fix:** `cross-env` (or `dotenv-cli`) in the `build` script; verify a Linux build in CI; keep `--webpack` only if the Linux Turbopack build also fails.

## 5. 🟠 High

### H1 — "AI processing" is mostly not AI
[lib/ai.ts](../lib/ai.ts) does:
- "paraphrase" = regex swaps (`according to` → `based on`) — `paraphraseBasic`, [ai.ts:190-215](../lib/ai.ts)
- "summarize" = first 8 sentences, hard-truncated at 900 chars — `summarizeToTwoParagraphs`, [ai.ts:312-318](../lib/ai.ts)
- "categorize" = weighted keyword regexes — `detectCategories`, [ai.ts:329-366](../lib/ai.ts)

The LLM is used **only for translation**. Published article bodies are therefore short, mechanically clipped text. Any claim of "AI rewriting/summarization" in older docs and in `README.md` overstates what runs.

### H2 — Refusal filter discards legitimate translations
`isRefusalLike`, [ai.ts:148-166](../lib/ai.ts): a translation is treated as a model refusal if it contains `sorry`, `policy`, `cannot provide`, … For a news platform, **`policy` is a normal news word** — those items silently fall back to LibreTranslate/MyMemory or untranslated source text. High false-positive rate by construction.

### H3 — API key prefix written to stdout
[ai.ts:109](../lib/ai.ts): `keyPrefix: safeKey.slice(0, 8)` is logged on every provider call. Remove; log only `hasKey`.

### H4 — No rate limiting at all
Login, signup, forgot-password, contact form, newsletter, cron endpoints — all unthrottled. Brute-force and spam are trivial.

### H5 — Weak secret-at-rest key in practice
`.env` has no `ADMIN_SECRET_ENCRYPTION_KEY` and no `ADMIN_SESSION_SECRET`, so both the session HMAC and the AES-256-GCM key derive from `NEXTAUTH_SECRET="development-secret-change-in-production"` ([security.ts:5-13](../lib/security.ts), [admin-auth.ts:15](../lib/admin-auth.ts)). Session forgery and secret decryption are possible for anyone who knows that string. If `NEXTAUTH_SECRET` were also unset, the hardcoded literals `"dev-admin-secret-change-me"` / `"unsafe-dev-fallback-key-change-me"` would be used.

### H6 — SEO is broken for a news product
Homepage, `/news`, `/article/[slug]`, `/events/[id]`, `/about`, `/contact`, `/media` are all `"use client"`. The **only** `metadata` export in the app is the global one in [app/layout.tsx:20](../app/layout.tsx) — there is no `generateMetadata` anywhere, so no per-article title/description/OG/canonical/JSON-LD. Meanwhile [app/sitemap.ts](../app/sitemap.ts) advertises up to 5000 article URLs whose content is not in the server HTML. Crawlers and social unfurls get an empty shell.

### H7 — Global over-fetching
[lib/context.tsx:175](../lib/context.tsx) loads `limit=100&full=1` (full article bodies) plus events, media and about on mount, and re-fetches on pathname change; on admin routes it additionally fetches subscribers, messages, stats and sources. This is the same root cause flagged in `docs_audit.md` (2026-03-13) — **still open**.

### H8 — Assistant memory stored in the contact-message table
[app/api/admin/assistant/route.ts:9](../app/api/admin/assistant/route.ts) persists chat memory as `ContactMessage` rows with `subject = "__assistant_memory__"` (and `__assistant_action__` for pending tool tokens). Domain mixing: these rows live in the inbox table and must be filtered out of every message query forever.

## 7. What works — don't re-audit these

- TypeScript compiles clean; dev server runs; Postgres connectivity and Prisma adapter (`PrismaPg`) are fine.
- `/api/admin/**` (except the intentionally public `auth/*`) **is** consistently guarded by `requireAdmin` / `getAdminSessionFromRequest`; `/api/admin/users` additionally enforces super-admin.
- Session tokens: HMAC-SHA256, httpOnly + SameSite=lax + `secure` in prod, 12h TTL, timing-safe compare, explicit `exp` check.
- Passwords: scrypt, 16-byte random salt, timing-safe verify.
- Integration secrets: AES-256-GCM with random IV + auth tag; plaintext never returned to the client; rotation endpoint + fingerprint only.
- Security headers (CSP, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy) set in [next.config.ts](../next.config.ts).
- Public read endpoints paginate and cap `limit` at 100, and send `s-maxage`/`stale-while-revalidate`.
- Telegram sender: retry with backoff, `sendPhoto` → `sendMessage` fallback, length clamping, HTML escaping.
- `robots.ts` + `sitemap.ts` exist and are server-rendered.

## 10. Reproducing this audit

```bash
npx tsc --noEmit                      # expect: clean
npx eslint .                          # expect: 1 error, ~112 warnings
npx prisma migrate status             # NOTE: does not detect schema.prisma drift
npx next dev --webpack --port 3111    # then: curl localhost:3111/api/health

grep -rl "approved\|isSuperAdmin\|resetToken" prisma/migrations/   # expect: empty → C3
```

Auth-coverage sweep (which routes reference a session helper):

```bash
for f in $(find app/api -name route.ts | sort); do
  grep -q "requireAdmin\|getAdminSession\|checkSuperAdmin" "$f" && echo "AUTH $f" || echo "---- $f"
done
```

Unauthenticated write probe (non-destructive — uses a non-existent id):

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST localhost:3000/api/frontend/articles -H "Content-Type: application/json" -d '{}'
curl -s -X DELETE localhost:3000/api/frontend/articles/00000000-0000-0000-0000-000000000000
```

`400`/`404` instead of `401` = the endpoint is unprotected.
