## 2. Critical fixes

### C1 — Content CRUD was unauthenticated
`requireAdmin(request)` added to every non-GET handler under `app/api/frontend/**`:
`articles` (POST), `articles/[id]` (PUT/DELETE), `events` (POST), `events/[id]` (PUT/DELETE),
`media` (POST), `media/[id]` (PUT/DELETE).

`POST /api/frontend/seed` was **deleted** — it seeded demo content *and created an admin
account with the hardcoded password `Admin123!`*, was referenced nowhere, and duplicated
`seed-db.js`. Content seeding: `node seed-db.js`; admin creation: `npm run admin:create`.

Deliberately still public: `GET` reads, `POST /api/frontend/contact`, `/subscribers`,
`/visits`, `/articles/view` — all now rate limited.

**Verified** (no cookies):

```
POST   /api/frontend/articles     -> 401      PUT    /api/frontend/events/x   -> 401
POST   /api/frontend/events       -> 401      DELETE /api/frontend/events/x   -> 401
POST   /api/frontend/media        -> 401      PUT    /api/frontend/media/x    -> 401
PUT    /api/frontend/articles/x   -> 401      DELETE /api/frontend/media/x    -> 401
DELETE /api/frontend/articles/x   -> 401      POST   /api/frontend/seed       -> 404
```

And with a valid admin session: create article `201`, delete `200` — the admin UI still works.

### C2 — Self-service privilege escalation
- `approved: true` removed from `auth/reset-password`. Approval now only comes from
  `POST /api/admin/users` (super admin).
- Reset tokens: missing expiry is treated as invalid, and the token is single-use.
- `auth/forgot-password` no longer builds links from the attacker-controlled `Host`
  header — it uses `APP_URL`/`NEXT_PUBLIC_SITE_URL`, falling back to `Host` only outside
  production. The reset link is returned in the response body **only** when
  `NODE_ENV !== "production"` (it used to leak whenever `Host` contained "localhost").
- The endpoint now answers identically whether or not the account exists.
- `auth/signup` normalises email to lower case (login/reset lookups were case-sensitive
  in one place and lowercased in another), validates username/email shape, and can be
  switched off with `ADMIN_SIGNUP_ENABLED=false`.
- A password reset stamps `passwordChangedAt`, which invalidates older sessions.

**Verified** — the full attack chain, with a throwaway account that was then deleted:

```
1. POST /api/admin/auth/signup           -> 200 "must be approved before you can sign in"
2. POST /api/admin/auth/login            -> 403 pending approval
3. POST /api/admin/auth/forgot-password  -> 200 generic answer (+ dev-only link)
4. POST /api/admin/auth/reset-password   -> 200 "still needs administrator approval"
5. POST /api/admin/auth/login            -> 403  ← the escalation is closed
6. reuse the same token                  -> 400 invalid/expired
DB: approved=false, isSuperAdmin=false, resetToken cleared, passwordChangedAt set
```

### C3 — Migration/schema drift
New migration `20260731000000_add_admin_approval_reset_and_assistant_memory` adds the four
`AdminUser` columns that existed only via `db push` (`approved`, `resetToken`,
`resetTokenExpires`, `isSuperAdmin`) plus the new `assistant_memory` table.
`20260731010000_add_password_changed_at` adds `passwordChangedAt`. Both are written with
`IF NOT EXISTS`, so they are safe on databases that were already pushed.

**Verified** on a throwaway database (`media_uwed_migtest`, created and dropped):

```
npx prisma migrate deploy                  -> 13 migrations applied
npx prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma
                                           -> "No difference detected."
```

CI now runs that same diff with `--exit-code`, so this drift cannot come back unnoticed.

### C4 — Open automation endpoints
New `lib/cron-auth.ts` accepts **either** an admin session (the UI triggers steps
manually) **or** the shared secret, via `x-automation-secret` or
`Authorization: Bearer` (the form Vercel Cron sends). It **fails closed**: with no secret
configured, scheduler access is refused instead of allowed.

Because a fabricated internal `Request` carries no credentials, the pipeline steps moved
out of the route files into `lib/pipeline/{pull,process,publish}.ts`; routes are now thin
auth+parse wrappers, and the scheduler and assistant call the functions directly.
(Next 16 also rejects non-handler exports from route modules, so this was required.)

**Verified**: all four endpoints `401` anonymously; correct secret `200`; wrong secret `401`.

### C5 — Production build failed → **root cause found**
Not a code defect: **the project lives on an exFAT volume** (`D:` is exFAT, `C:` is NTFS).

- exFAT has no reparse points, so `fs.readlink()` on a plain file returns `EISDIR` where
  webpack's resolver expects `EINVAL` → `Failed to compile`. Proven directly:
  file on `D:` → `EISDIR`, identical file on `C:` → `EINVAL`.
- exFAT also rejects `:` in filenames, so Turbopack cannot write its
  `[externals]_node:buffer_*.js.map` chunk → `os error 123`.

Neither is fixable from `next.config.ts` (`resolve.symlinks: false` and `cache: false`
were both tried and rejected — see the note left in that file). Copying the project to
`C:` and building: **both bundlers succeed**.

The `build` script also used POSIX-only `VAR=value cmd` syntax, which fails on Windows;
it is now `prisma generate && next build`, with `build:webpack` kept as an escape hatch.
The duplicate `vercel-build:with-migrate` script was removed.

## 3. High-severity fixes

### H1 — "AI processing" now actually uses the model
`lib/ai.ts` gained `processNewsWithLlm()`: **one** structured call per article that
rewrites, summarises, translates to EN/RU/UZ and categorises, returning JSON that is
parsed tolerantly (models wrap output in prose or ``` fences). Categories are validated
against a fixed vocabulary so the taxonomy cannot drift.

Why one call instead of the old per-chunk translation loop: the model sees the whole
article, so terminology stays consistent instead of being stitched from 450-character
chunks; it genuinely rewrites (republishing a feed verbatim is plagiarism) instead of
applying regex synonym swaps; and it costs one request instead of up to nine.

The heuristic pipeline remains as an automatic fallback when no key is configured or the
call fails. Its 900-character clamp — which visibly truncated published bodies — is now a
parameter: summaries stay short, article bodies get 40 sentences / 4000 characters.

**Verified** two ways, both against a local stub provider (no key, no network):

- `npm run check:ai` — 7 assertions: fenced JSON parsed, all three languages, paragraphs
  preserved, invalid category dropped, editorial prompt forwarded.
- A full `runProcess()` run against a real queued item: 1 provider call, row stored as
  `pending_review` with all three languages and `University, Science` categories,
  paragraphs intact. Database state restored afterwards.

### H2 — Refusal filter no longer eats real translations
`isRefusalLike()` rejected any output containing `policy` or `sorry` — catastrophic for a
news site (every article about government policy was silently downgraded to a free
translator). It now only inspects the opening of short outputs and requires a
first-person refusal pattern.

### H3 — No key material in logs
`keyPrefix: safeKey.slice(0, 8)` removed. Error paths no longer log response *headers*
(which carry credentials), only status, message and a truncated body. `logger.debug()`
added, suppressed in production.

### H4 — Rate limiting
`lib/rate-limit.ts`, fixed-window per IP, applied to login (10/min), signup /
forgot-password / reset-password (5/15min), password change, contact form and newsletter
(20/min), and pipeline triggers (6/min). In-process, so per-instance on serverless — the
limitation is documented in the file; move to Redis for strict guarantees.

**Verified**: attempts 1-10 → `401`, 11-12 → `429` with `retry-after: 59`.

### H5 — Real secrets
`ADMIN_SESSION_SECRET`, `ADMIN_SECRET_ENCRYPTION_KEY` and `AUTOMATION_CRON_SECRET`
generated (48/48/32 random bytes) and appended to `.env`; the previous file was copied to
`.env.backup-before-hardening`. Safe to rotate the encryption key here because no
integration secrets were stored yet. **Existing sessions were invalidated — sign in again.**

`.env.example` now documents every variable, and `.gitignore` was fixed so the template
is committed while real `.env` files stay ignored.

### H6 — SEO
`/article/[slug]` is now a server component: it loads the article with Prisma, returns
`notFound()` when missing, exports `generateMetadata()` (title, description, canonical,
Open Graph `type=article` with published/modified times, Twitter card) and emits
`NewsArticle` JSON-LD. The interactive parts moved to `article-view.tsx`, which receives
the article as a prop — so the full text is in the initial HTML.

`lib/site-url.ts` centralises the public origin (`APP_URL` → `NEXT_PUBLIC_SITE_URL` →
Vercel-provided → localhost) and is used by the layout, sitemap and robots. `robots.ts`
now also disallows `/api/cron`.

**Verified** on a real article: `<title>`, `og:title`, `og:type=article`, `description`,
`rel=canonical`, `application/ld+json` with `"@type":"NewsArticle"`, and 4 rendered
paragraphs — all present in the server HTML.

### H7 — Over-fetching
The shared context no longer requests `full=1`, so admin page loads stopped transferring
100 complete article bodies. The admin editor fetches the one article it is editing. The
duplicate mount fetch on admin routes (two effects both firing) was merged into one.

### H8 — Assistant memory
New `assistant_memory` table and `lib/assistant-memory.ts`. Previously chat memory and
pending tool tokens lived in `contact_messages` behind magic `subject` values — and since
the public contact form let the caller choose `subject`, **any visitor could write
straight into the admin assistant's context**. The contact form now rejects reserved
subjects, and inbox queries filter legacy rows.

Also fixed while in there: confirmation tokens for destructive assistant actions were
`Math.random()` — now `randomBytes`, with a 10-minute TTL, and the token is consumed
*before* the action executes so a replayed `/confirm` cannot run it twice.

**Verified**: `/status` round-trip stores two rows in `assistant_memory`;
`contact_messages` stays empty; a contact submission with
`subject: "__assistant_memory__"` is stored as `General Inquiry` and reaches no
assistant row.

## 6. What still needs a human

1. **Move the project to an NTFS drive** (e.g. `C:\Dev\Media-uwed`) or build in CI/WSL —
   otherwise no production build can be made locally (§C5). Development (`npm run dev`)
   works fine on exFAT.
2. **Set `APP_URL`** to the real public origin. Until then canonical URLs, Open Graph
   tags, the sitemap, Telegram links and password-reset emails all point at localhost.
3. **Configure an AI provider key** in Admin → Automation → Integrations (or
   `OPENROUTER_API_KEY`). Without it the pipeline silently uses the weak heuristic path.
4. **Configure email** (`RESEND_API_KEY`, `RESEND_FROM_EMAIL`) or password reset only
   works via the server log.
5. **Copy the three generated secrets** from `.env` into the production environment, and
   set `CRON_SECRET`/`AUTOMATION_CRON_SECRET` on the host so the scheduler can run.
6. **Sign in again** — the session secret changed, so existing cookies are invalid.
7. **Review the RSS sources**: they are general news feeds (Gazeta.uz, TASS, RIA, plus a
   Reuters URL that has never fetched successfully), not university sources.
8. **Decide on `ADMIN_SIGNUP_ENABLED`** — public registration is still on (gated by
   super-admin approval). Set it to `false` once the team has accounts.
9. **Add tests.** `npm run check:ai` is a start; `lib/security.ts`, `lib/admin-auth.ts`,
   `lib/safe-fetch.ts` and the auth routes deserve real unit/integration tests.
