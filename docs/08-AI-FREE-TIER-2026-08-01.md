# Running the AI pipeline on OpenRouter's free tier (2026-08-01)

The deployment uses an OpenRouter account with **no purchased credit**, so only `:free`
model variants are usable. This document records what that constrains, what the code now
does about it, and what still has to be done by hand.

Previous document: [07-HARDENING-2026-07-31.md](07-HARDENING-2026-07-31.md).

---

## 1. What the free tier actually allows

Confirmed against OpenRouter's rate-limit documentation on 2026-08-01:

| | Limit |
|---|---|
| Requests per minute | 20, across all `:free` models |
| Requests per day | **50** while lifetime credit purchased is under $10 |
| Requests per day | 1000 once $10 has ever been purchased |
| Response when exceeded | `429`, message `Rate limit exceeded` |

Limits are governed per user, not per key: extra accounts or keys do not raise them.

The pipeline spends **one request per article** (the single editorial pass produces EN, RU
and UZ together), so 50 requests/day is roughly **40 articles/day** after leaving room for
the admin assistant chat. The queue currently holds 236 unprocessed articles, i.e. about
six days of backlog at the free rate.

## 2. Changes made

### 2.1 Default model is now a free variant

`openai/gpt-4o-mini` (paid, and dead without credit) was the default in five places.
All now resolve to `DEFAULT_AI_MODEL` in [lib/ai.ts](../lib/ai.ts):
`google/gemma-4-31b-it:free`.

Verified against the live catalogue (`GET https://openrouter.ai/api/v1/models`) — 14 `:free`
models exist today; the chosen ones are among them and advertise `response_format`.

> The default is provisional. Run `npm run check:models` once a key is configured and pick
> the winner on the Uzbek samples — see §4.

### 2.2 Fallback chain instead of a single model

Free capacity is shared between all OpenRouter users and is frequently busy, so a single
model means dropping to the weak offline heuristics far more often than necessary. The
editorial pass now walks a chain: the configured model, then
`OPENROUTER_FALLBACK_MODELS` (defaults to gemma-4-26b → nemotron-3-super-120b →
gpt-oss-20b).

A model is abandoned and the next one tried on: `429`, `402`, `5xx`, a timeout, an empty
message (reasoning models sometimes spend the whole completion budget thinking), output
that is not JSON, output that is a refusal, or output missing the source language.
`401`/`403` abort the whole chain — a broken key fails identically everywhere, so there is
no point paying one request per candidate to learn that.

### 2.3 Self-healing request shape

The first request per model asks for `response_format: {type: "json_object"}` and
`max_tokens: 8000` (three languages of article body do not fit in the default completion
cap of several free endpoints, which truncates the JSON mid-string). Free endpoints differ
in which parameters they accept, so a `400`/`422` retries the **same** model once with a
plain body rather than treating it as unusable. No hardcoded capability table to go stale.

### 2.4 Reasoning preambles

Most of the free tier is reasoning-tuned and emits `<think>…</think>` before the answer.
Those blocks are stripped before JSON extraction — braces inside the reasoning would
otherwise anchor the brace-slice to the wrong opening brace.

### 2.5 The heuristic fallback no longer spends requests

This was the expensive bug. When the editorial pass failed, the offline fallback path
called the provider **again, once per 450-character chunk** — up to nine extra requests per
article. On a 50-request day that burnt the entire quota on about five articles and then
failed anyway, since a failing editorial call and a failing chunk call almost always share
one cause (rate limit, bad key, data policy).

`translateWithOpenRouterChunk` is gone. The fallback chain is now LibreTranslate →
MyMemory → untranslated source, and the provider is called exactly once per article, by
the editorial pass.

### 2.6 Daily request budget

New table `ai_usage_days` (migration `20260801000000_add_ai_usage_day`) counts requests per
UTC day — the same reset boundary OpenRouter uses. [lib/ai-usage.ts](../lib/ai-usage.ts)
owns it; both the pipeline and the admin assistant chat record against it.

`AI_DAILY_REQUEST_LIMIT` (default **40**, `0` disables metering) caps the pipeline. When the
budget is spent, remaining articles **stay queued** instead of being processed by the
heuristics — they keep their place and get a real editorial pass after the reset. The run
result reports `aiBudget` and splits the batch into `llmArticles` / `heuristicArticles`, so
a run that quietly went all-heuristic is visible instead of being discovered later in the
published output.

A per-article cap (`MAX_REQUESTS_PER_ARTICLE = 3`) stops one stubborn article from eating a
large slice of the day.

### 2.7 Model ids containing `:` were being silently discarded

`normalizeModel` in the assistant route validated ids against `/^[a-z0-9._/-]+$/i`, which
**rejects the colon in every `:free` id** and fell back to the default. Any free model
configured for the assistant chat was silently ignored. `:` is now allowed.

### 2.8 The pipeline had nothing to rewrite (the defect behind everything else)

Measured before any of the above mattered: `scrapeArticleDetails` returned **0 characters
for every configured source**. `lib/scraper.ts` extracted text only from `<p>` elements,
and RIA — one of the three seeded feeds — marks paragraphs up as
`<div class="article__text">` and serves pages with **zero** `<p>` tags. RIA's feed also
carries no `description` at all, so the editorial pass received a bare headline and
invented the rest: asked to produce "3-6 paragraphs" from a 70-character headline, a model
returned a textbook explanation of what lending statistics are.

The extractor was rewritten to work without assuming `<p>`:

1. `articleBody` from JSON-LD, when the site publishes it — the body the publisher itself
   declares, no markup guessing;
2. otherwise, score the known body containers (`[itemprop=articleBody]`, `article`,
   `.article__body`, …) and walk block elements generically, dropping blocks whose text is
   more than 40 % inside links (navigation and "related articles"), and dropping any
   candidate that contains another candidate so wrapper `div`s are not counted twice;
3. otherwise the whole `<body>`.

Result on the same URLs: RIA 0 → **1292** characters (10 paragraphs), Gazeta.uz 0 →
**1671**.

**Thin sources.** Some publishers cannot be scraped at all — TASS article pages return a
1.5 KB bot-block shell. So the prompt now adapts instead of inviting invention:

| Source material | Behaviour |
|---|---|
| ≥ 400 characters | Full article, 3-6 paragraphs |
| 120–400 characters | Brief mode: 1-3 sentences, and the prompt forbids background, context, definitions and consequences |
| < 120 characters | **Not processed at all** — left queued, counted as `skippedThinSource` |

A headline cannot become an article without inventing the article, and a university
masthead cannot publish that.

### 2.9 RSS ingestion rewritten around what feeds actually send

Each configured feed's raw XML was inspected rather than assumed:

| Feed | What it really sends |
|---|---|
| Gazeta.uz | Full lead paragraph — but with `&nbsp;`, `&laquo;`, `&mdash;` **inside CDATA**, which XML parsing does not decode, so those literal characters were being published |
| TASS | One-sentence teaser; no image; article pages bot-blocked |
| RIA | No description whatsoever; image in a typed `enclosure` |
| Reuters | HTTP 404 — dead |
| Kun.uz `/ru` | **Invalid XML** — a bare `&` in a title aborted the parse and lost all 20 items |

Changes to `lib/rss.ts`:

- `content:encoded` and `yandex:full-text` are now captured. Feeds that ship the whole
  article (Times of Central Asia: 10/10 items; UzA: 7-8/20) need **no scraping at all** —
  the text is stored into `rawJson.fullContent`, which the processing step already reads.
- HTML entities are decoded and tags stripped while preserving paragraph breaks.
- Images are resolved from `enclosure`, `media:content`, `media:thumbnail`, `media:group`,
  `itunes:image` and finally an inline `<img>`, and are **type-checked**: a podcast
  `enclosure` of `audio/mpeg` is no longer used as an article photo.
- Invalid XML is repaired once (bare ampersands, forbidden control characters, leading BOM)
  before giving up on a source.
- A feed refresh no longer overwrites an already-scraped body: `rawJson` is merged, and an
  item that stops sending an image no longer blanks the stored one.

`npm run check:rss` locks all of this down with **24 offline assertions**, one per feed
shape above. It parses XML directly rather than serving it over localhost, because the
SSRF guard correctly blocks localhost and weakening a security control for a test is the
wrong trade.

### 2.10 Sources replaced

`npm run seed:sources` installs the list, idempotently, and disables rather than deletes
what should stop running so existing articles keep their foreign key:

| Enabled | Why |
|---|---|
| UzA RU + UZ | National agency; 7-8 of 20 items carry full text, all 20 have images |
| Gazeta.uz RU + UZ | Teasers plus images; bodies scrape cleanly |
| UzDaily EN | English-language economy coverage |
| Spot.uz | Business and technology |
| Times of Central Asia EN | Regional diplomacy; **all** items ship full text |
| Kun.uz UZ | Uzbek-language general news |

| Disabled | Why |
|---|---|
| RIA Novosti | Headline-only feed about Russian domestic politics — off-topic for a university masthead |
| TASS | Teaser-only and bot-blocked, so bodies cannot be obtained |
| Reuters | 404 |

`uwed.uz` itself has no RSS feed (404 on `/rss` and `/feed`), so university news has to be
entered by hand or the site needs a feed added.

First pull on the new list: **135 new items, zero feed errors**, every source returning
teasers, 27 items carrying full text, 152 of 176 with an image.

## 4. Done, and what is still open

The key is configured (stored encrypted in the integration row and in `.env`), the model
was chosen by measurement, and the pipeline has been run end to end on live feeds. What
remains is listed below — none of it blocks the pipeline, all of it blocks a public launch.

### Open — content and presentation

1. **`app/about/page.tsx` shows fabricated people.** `defaultAboutPageConfig` ships
   "Sarah Connor", "James T. Kirk" and "Nyota Uhura" with invented `@university.edu`
   addresses, a US phone number, "Student Center, Room 304", and "Established in 1995".
   The `about_content` table is empty, so those defaults are what the public page renders
   today. Replace with real UWED contacts, or leave the team empty and hide the section.
2. **`about` page config lives in `contact_messages`** under the magic subject
   `__about_page_config__`, and every save **creates a new row** instead of updating one.
   Same anti-pattern that was removed from the assistant in `07` §H8: internal state in the
   public inbox table, growing without bound. Needs its own table.
3. **Media section is empty** (0 rows), so the homepage renders "Multimedia Highlights"
   and "Latest Videos" as empty grids, and the hero shows the admin instruction
   *"Set media category to 'hero-side' from Admin Media to show content here"* — to the
   public.
4. **Hardcoded English on otherwise trilingual pages**: "News Archive", "Show filters",
   "By {author}", "Read More", "Loading portal…", "Start Watching", "Featured slot".
5. **Dates are raw strings** (`Article.date` is `String`), never formatted per locale.
6. **The homepage is client-only** (`"use client"`), so crawlers get an empty shell. The
   article page was fixed in `07` §H6; `/`, `/news`, `/events`, `/media` were not.
7. **`uwed.uz` has no RSS feed**, so the university's own news cannot be ingested — it has
   to be entered by hand or a feed has to be added on their side.

### Open — from the older backlog (`05-RECOMMENDATIONS.md`)

8. `SiteSettings.enableComments` / `moderateComments` are exposed in Settings and do
   nothing — no comment model exists. Either implement or remove the toggles.
9. Missing indexes: `Source(enabled, lastFetchedAt)`, `ArticleProcessed.status`.
10. No test suite beyond `check:ai` (27) and `check:rss` (24) — no tests for
    `security.ts`, `admin-auth.ts`, or any route.
11. `M4`: `app/admin/(protected)/automation/page.tsx` is 1487 lines.

### Operational notes

- **Check OpenRouter → Settings → Privacy** if a model returns `404` with a data-policy
  message: there are separate toggles for free and paid models.
- **$10 of credit** raises the daily cap from 50 to 1000 requests (one-time, not a
  subscription). Then raise or zero `AI_DAILY_REQUEST_LIMIT`.
- **Uzbek quality is imperfect on free models.** Observed in a live run:
  "223 ta **ukrayna** dronlarini" (should be *Ukraina*), "**moscva** vaqti",
  "ro'yx**siz**". Readable and factually right, but every article needs an editor — which
  is why they land in `pending_review` rather than being published.

## 5. Configuration reference

| Variable | Default | Purpose |
|---|---|---|
| `OPENROUTER_API_KEY` | — | Fallback key when none is stored in the admin UI |
| `OPENROUTER_TRANSLATE_MODEL` | `google/gemma-4-31b-it:free` | Editorial pass model |
| `OPENROUTER_ASSISTANT_MODEL` | `google/gemma-4-31b-it:free` | Admin assistant chat model |
| `OPENROUTER_FALLBACK_MODELS` | gemma-4-26b, nemotron-3-super-120b, gpt-oss-20b (all `:free`) | Tried in order when the primary fails |
| `AI_DAILY_REQUEST_LIMIT` | `40` | Requests per UTC day; `0` disables metering |

The model stored in Admin → Automation → Integrations takes precedence over
`OPENROUTER_TRANSLATE_MODEL`, which takes precedence over the built-in default.
